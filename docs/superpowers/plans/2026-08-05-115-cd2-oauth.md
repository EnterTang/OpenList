# 115 CD2 OAuth Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `115-cd2` use CloudDrive2's real web OAuth flow by default, receive the token pair through an OpenList callback, and persist it without weakening the existing CD2 refresh relay or directory APIs.

**Architecture:** Keep the existing `115_open` API delegate and CD2 refresh transport. Add a CD2 OAuth state machine around storage initialization: when credentials are absent, generate a one-time state and an authorization URL using client ID `100195313` and redirect URI `https://redirect115.zhenyunpan.com`; persist the pending state; expose a public callback that validates the storage ID/state, persists the returned `access_token`/`refresh_token`, and reloads the storage. Retain the existing device-code flow as an explicitly selectable compatibility mode so existing QR-based configurations are not broken.

**Tech Stack:** Go, Gin, GORM-backed storage persistence, `115-sdk-go`, existing OpenList driver lifecycle and test helpers.
