# 115-sy 行为兼容驱动设计

## 1. 背景

当前 OpenList 的普通 115 驱动依赖 `github.com/SheltonZhu/115driver`，登录探针在 `LoginCheck()` 阶段可能返回 `40101017`，表现为“用户验证失败”。仅升级依赖不能保证解决问题：当前上游版本仍然采用相同的 SSO 检查路径，且该错误发生在目录读取之前。

本设计新增一个独立的 `115-sy` 驱动，目标是参考 Symedia 的 115 行为重新实现，而不是继续扩展现有 `drivers/115`，也不直接复用现有 115 SDK。实现使用原生 Go，行为兼容即可，不恢复或破解 Symedia 的 PyArmor 源码。

## 2. 证据与边界

已核验的 Symedia 镜像为 `shenxianmq/symedia:latest`，镜像标签包含：

- source：`https://github.com/shenxianmq/Symedia-amd`
- revision：`861e4bfb1d12e9ef0b39fe41c93be1542c59f448`
- version：`1.0.59.32`
- digest：`sha256:92352bb398d2bf46be4ae66b6eceb4fa9b00874a806fba86ea79ae05b558fce5`

镜像内能够确认以下事实：

- Symedia 包含独立的 `apps/p115client`、`patches/patch_manager.py`、`plugins/helper115`、`Clean115`、`FastDelete115Dirs`、`SecUpload115`、`TreeSync`、`StarSync` 和 AutoSymlink/P115PathBuilder 组件。
- 其依赖包含 `p115client==0.0.9.3.11`、`p115cipher==0.0.5.4`、`p115oss==0.1.0.3`、`p115pickcode==0.0.5.4`。
- Symedia 包装层可看到 Web API 的 `files/files/getid` 和 `files/share/receive` 调用；官方 p115client SDK 暴露 `fs_files_app`、`fs_dir_getid`、`share_snap_app`、`share_snap`、`share_receive`、`clouddownload_task_add_urls`、`recyclebin_clean`、`download_url` 和 `user_my_info` 等能力。
- Symedia 配置模型中的 `Settings115` 包含账户名称、Cookie、状态和 ID；`Helper115Config` 中的分享目标和离线目标以字符串配置表达。

部分 Symedia 模块受到 PyArmor 保护，无法把加密实现当作可复用源码。因此本设计只采用可观测的接口、数据和行为，不声称复原其内部实现细节。

## 3. 目标与非目标

### 3.1 目标

新增一个用户可选择的 `115-sy` 存储驱动，提供：

- Cookie 登录、状态检测和独立 QR 登录能力；
- Web/Android 请求 profile、限速、分页冷却和受控 fallback；
- 115 CID/FID 到 OpenList 对象和 POSIX 路径的映射；
- 浏览、直链、目录和文件基础操作；
- 分享解析、快照、转存；
- Magnet、ED2K、HTTP/HTTPS 离线任务；
- 普通上传和秒传优先上传；
- TreeSync、StarSync、清理、快速删除和定时任务等可复用自动化服务；
- 结构化错误、脱敏日志和可测试的 HTTP 合约层。

### 3.2 非目标

- 不修改现有 `drivers/115`、`drivers/115-open` 或 `drivers/115-cd2` 的现有行为；
- 不在新驱动中导入 `github.com/SheltonZhu/115driver`；
- 不实现 Telegram 或微信的具体 UI、Bot 命令和回调协议；
- 不恢复、破解或分发 PyArmor 加密代码；
- 不承诺绕过 115 的验证码、风控或账户安全策略；
- 不把 Symedia 的本地 `.strm` 文件生成强行塞进核心挂载接口，核心通过 OpenList 的直链返回完成等价能力。

## 4. 总体架构

代码按职责拆分为三层，外部只注册一个 `115-sy` 驱动：

```text
drivers/115_sy
        │
        ├── Mount Layer       OpenList Driver、路径、对象、CRUD、直链
        ├── Client Layer      Cookie、QR、请求 profile、限速、响应、错误
        └── Service Layer     分享、离线、上传、同步、清理、调度
```

建议目录：

```text
drivers/115_sy/
    driver.go

internal/115sy/

```

具体文件名可以按现有仓库约定调整，但新驱动不能依赖旧 115 客户端包。

## 5. 客户端、认证与请求策略

### 5.1 独立客户端

`internal/115sy.Client` 自己持有 HTTP Client、Cookie Jar、请求 profile、限速器和可取消请求上下文。不得使用全局 Cookie、全局可变 User-Agent 或旧驱动的登录状态。

支持两个基础 profile：

- Web：115 Browser 兼容请求头和 Web API；
- Android：Android App 兼容请求头、`app` 标识和 `appversion`。

允许显式传入 User-Agent；未提供时使用 profile 默认值。显式空 User-Agent 不被随机替换，以兼容 CDN 直链对 Header 的要求。

### 5.2 Cookie 登录

Cookie 导入后按以下顺序验证：

```text
解析 Cookie
    ↓
user_my_info 或等价用户信息探针
    ↓
根目录 CID 探针
    ↓
认证成功
```

Cookie 解析至少识别 UID、CID、SEID；KID 为可选字段。认证状态必须区分 Cookie 缺失、格式错误、过期、业务验证失败和网络错误。

定义结构化认证错误：

```go
type AuthError struct {
    Errno   int
    Message string
    Stage   string
    Profile string
}
```

`40101017` 只允许有限次、按策略选择 profile 的重试，不能无限重试，也不能声称已经绕过验证。

### 5.3 QR 登录

QR 登录与 Cookie 导入互相独立，包含：二维码生成、轮询、确认、Cookie 提取、登录探针和状态过期。QR 轮询必须有超时、取消和最大次数，避免后台任务永久运行。

### 5.4 请求 fallback

各类请求使用明确的首选 profile 和备用 profile：

| 操作 | 首选 | 备用 |
| --- | --- | --- |
| 用户信息 | Web | Android |
| 目录列表 | Android | Web |
| 分享快照 | Android | Web |
| 分享转存 | Web | Android |
| 下载链接 | Web/Chrome | Android |
| 离线任务 | Android | Web |

只有网络错误、HTTP 405/指定兼容状态或明确的 profile 不支持才允许 fallback。认证失败、参数错误、目标目录不存在和风控错误直接返回结构化错误。

统一处理顺序为：

```text
网络错误 → HTTP 状态 → JSON 解码 → errno → 允许的 fallback → typed error
```

## 6. 文件系统挂载与直链

### 6.1 对象模型

目录使用 CID，文件使用 FID。根目录 `/` 固定映射到 CID `0`。对象保留以下远端字段：

```go
type Item struct {
    ID         string
    Name       string
    IsDir      bool
    Size       int64
    SHA1       string
    PickCode   string
    ParentCID  string
    ModifyTime time.Time
    Thumbnail  string
}
```

### 6.2 路径解析

提供 `ResolvePath` 和 `ResolveCID`：

- 规范化 `/`、`.`、`..`；
- 禁止从挂载根目录逃逸；
- 优先使用 Symedia 观察到的路径查询语义；
- 不支持时使用标准 Web `getid` 语义；
- 目录查询结果缓存必须可失效，不能永久信任旧 CID。

### 6.3 分页与冷却

目录读取通过 Android 文件列表接口分页完成，直到达到总数或 `has_more=false`。必须具备：

- 最大 page size；
- 页间 cooldown；
- 账户级限速；
- context 取消；
- 重复 offset、空页循环和重复对象保护；
- 业务错误和 HTTP 错误的区分；
- Android 到 Web 的受控 fallback。

`PageSize`、`PageCooldown`、`RateLimit` 作为配置项，默认采用保守值。

### 6.4 直链

文件直链优先使用 pickcode 生成。返回 URL 时同时保留必要的 User-Agent、Cookie 或其他 Header 元数据，供 OpenList 的 Link 语义使用。

直链错误必须区分：

- 文件不存在；
- pickcode 无效；
- URL 为空；
- CDN 403；
- Cookie 失效；
- profile 不兼容。

### 6.5 文件操作

实现 OpenList 可选接口：

- `MakeDir`；
- `Move`；
- `Rename`；
- `Copy`；
- `Remove`；
- `Put`；
- `Link`/等价直链接口。

所有操作都经过统一的限速、请求、errno、重试/fallback 和错误映射管线。

## 7. 分享、离线与上传

### 7.1 分享链接与快照

分享解析只负责格式识别，不在解析阶段访问网络。统一模型为：

```go
type ShareURL struct {
    ShareCode   string
    ReceiveCode string
    SourceURL   string
}

type ShareSnapshot struct {
    ShareCode   string
    ReceiveCode string
    RootID      string
    Name        string
    FileCount   int64
    TotalSize   int64
    Items       []ShareItem
}
```

快照优先使用 `share_snap_app`，在 HTTP 405、限流或明确接口不兼容时使用 `share_snap`。解析时防止分页重复、空成功响应、目录循环和无限递归。

### 7.2 分享转存

分享目标兼容 Symedia 的配置语义，例如 `电影:1001,电视剧:1002`，同时允许 JSON 表达。转存请求包含分享码、提取码、目标 CID 和可选文件 ID。

转存结果逐项保留成功状态和错误原因，不能把 HTTP 成功等同于所有文件转存成功。完成后刷新目标目录缓存，并异步触发媒体扫描联动。

### 7.3 离线任务

支持 Magnet、ED2K、HTTP/HTTPS。提交前按行拆分、过滤空行、去重，调用 `clouddownload_task_add_urls`，并保留每个 URL 的任务 ID、状态和错误信息。

需要区分任务已存在、配额不足、链接非法、目标 CID 不存在、Cookie 失效和风控错误。批量提交完成后最多触发一次目标目录刷新。

### 7.4 上传与秒传

上传先计算文件大小、SHA1 和首块 SHA1，优先尝试秒传；只有明确的“未命中/不可复用”结果才降级为普通分片上传。认证、风控和目标目录错误不能静默降级。

OSS 上传适配层保留 Symedia 对 `appversion` 和 Android User-Agent 的兼容处理，并集中管理版本常量。秒传成功后删除本地源文件、生成分享等副作用均默认关闭，必须显式配置。

## 8. 自动化服务

### 8.1 TreeSync 与 StarSync

TreeSync 解析 115 导出的 UTF-8/UTF-16 目录树，构建 CID/FID、路径和父目录关系，支持增量更新，解析失败时保留上一次有效索引。

StarSync 只同步目录结构，不默认扫描所有文件元数据，适用于大目录账户。

### 8.2 清理与快速删除

Clean115 支持按配置清理目录、过期规则和可选安全码清空回收站。删除过程先产生待处理对象摘要，逐项保留失败原因。

FastDelete115Dirs 支持批量切分、有限并发、批次重试和取消。默认禁止递归删除挂载根目录。

### 8.3 任务调度

后台任务统一包含 ID、类型、状态、进度、创建时间、更新时间和脱敏错误信息，支持手动触发、Cron、查询、取消、账户级并发限制和可恢复任务。

调度任务必须复用客户端限速器，不能绕过请求冷却直接并发访问 115。

## 9. 管理、安全与可观测性

### 9.1 管理入口

先提供可复用 Go 服务接口，再按 OpenList 现有管理 API 规范接入。管理能力包括 Cookie/QR 状态、分享快照、分享转存、离线任务、同步、清理、删除和后台任务查询。

所有管理操作必须经过 OpenList 管理权限控制。

### 9.2 敏感信息

- Cookie 只进入配置存储，不进入普通日志；
- Cookie、提取码、安全码和带敏感参数的下载 URL 必须脱敏；
- 安全码只在请求期间使用，不保存进任务日志；
- 错误消息不得回显完整认证材料。

### 9.3 删除保护

清空回收站、递归删除、大规模并发删除和秒传后删除本地源文件必须显式配置或二次确认，默认关闭危险副作用。

### 9.4 结构化日志

请求日志记录账户、profile、endpoint、operation、HTTP 状态、errno、重试次数和延迟，但不记录认证材料。错误分类为网络、HTTP、115 业务、认证、风控、参数、本地解析和任务取消。

## 10. 测试与验收

### 10.1 单元测试

覆盖 Cookie 解析、分享链接解析、路径规范化、分页去重、目录树解析、离线结果解析、errno 映射、直链 Header、配置解析和删除保护。

### 10.2 HTTP 合约测试

使用本地 Mock Server 验证 Web/Android profile 选择、HTTP 405 fallback、40101017 的有限重试、业务 errno、上传初始化参数、分页冷却、取消和日志脱敏。

### 10.3 实机验收

至少验证：

1. Cookie 登录和状态检测；
2. QR 登录；
3. 根目录、多级目录和大目录分页；
4. 文件直链播放；
5. 创建、移动、重命名、复制和删除；
6. 普通上传；
7. 秒传命中与未命中；
8. 分享快照与转存；
9. Magnet/ED2K 离线任务；
10. TreeSync 或 StarSync；
11. 回收站清理保护；
12. 过期 Cookie 和 `40101017` 的明确错误提示。

最终验收标准：`115-sy` 不依赖 `github.com/SheltonZhu/115driver`，可以独立完成 Symedia 相关 115 能力的行为兼容实现，同时现有 115 系列驱动行为不发生变化。

## 11. 交付阶段

### 阶段 A：核心挂载

完成独立客户端、认证、QR 登录、路径/CID、分页、冷却、直链、CRUD、普通上传、秒传基础能力和容量信息。

### 阶段 B：传输能力

完成分享解析/快照/转存、Magnet/ED2K/HTTP 离线任务、任务查询/删除和结构化结果。

### 阶段 C：自动化能力

完成 TreeSync、StarSync、回收站清理、快速删除、Cron 清理和秒传 watcher 等服务。Telegram/微信交互不直接移植，但这些交互所需的底层能力均通过 Go 服务保留。

阶段 A 完成并通过实机验收后，才将驱动作为稳定功能暴露；阶段 B、C 可以独立迭代，但不能改变阶段 A 的挂载和直链语义。
